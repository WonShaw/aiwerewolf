# AI 狼人杀

一群 AI（Claude Opus 5.5）玩狼人杀，目前支持 12 人预女猎白。人可以在网页上观战，也可以入座和 AI 一起玩。

架构沿用了 aivalon（AI 阿瓦隆）：每个 AI 玩家是一个 Claude Agent SDK 会话，服务端是唯一知道全部信息的地方，按观看者过滤推送。

## 运行

需要 Node 20+，并且本机已登录 Claude Code（AI 玩家通过 Claude Agent SDK 调用，使用 Claude Code 的登录凭证）。

```bash
npm install
npm run dev
```

打开 http://localhost:5181 。后端 API 在 8788 端口，可以用 `AIWEREWOLF_API_PORT` 修改。端口和 aivalon 错开，两个项目可以同时运行。

### 局域网联机

前端开发服务器监听所有网卡，`npm run dev` 启动后终端里 `Network:` 那一行就是局域网地址。

- 开局的人请用这个局域网地址打开大厅再创建对局，这样生成的玩家专属链接别人才能打开。
- 其他人只需要访问 5181 端口，前端会把 `/api` 转发到本机的后端。
- 也可以先 `npm run build` 再 `npm start`，这时后端在 8788 端口同时提供页面和 API。

注意：同一局域网里的任何人都能打开大厅、开新局（消耗你的 Claude 额度）和删除已结束的对局。只在信任的网络里这样用。

可选环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `AIWEREWOLF_MODEL` | `claude-opus-5-5` | AI 玩家使用的模型 |
| `AIWEREWOLF_EFFORT` | `medium` | 推理强度 |
| `AIWEREWOLF_THINKING_DISPLAY` | `summarized` | 设为 `omitted` 后不再获取思考摘要 |
| `AIWEREWOLF_NIGHT_MIN_MS` | `6000` | 有人类玩家时，夜里每一步至少等待的毫秒数 |

其他命令：

- `npm run simulate`：用脚本玩家跑几百局完整对局（不调用模型），检查规则结算、胜负判定和信息可见性，并确认每条规则分支都被走到
- `npm run check-isolation`：调用一次模型，让 AI 报告它的上下文里有哪些工具和附加信息
- `npm run typecheck` / `npm run build`

## 规则

12 人：狼人 4 名；神职 4 名（预言家、女巫、猎人、白痴）；平民 4 名。

**夜晚**（依次进行）：
1. 狼人按座位依次发言商量（只有狼人能看到），每人提议一个袭击目标；以多数提议为准，平票随机。可以袭击任何存活玩家，包括狼人自己。
2. 女巫：解药、毒药各一瓶，同一晚只能用一瓶；解药还在时才知道当晚谁被袭击；不能自救。
3. 预言家查验一名玩家是好人还是狼人。

女巫或预言家出局后，对应的步骤照常空过。

**白天**：
1. 第一天先竞选警长（第一晚的死讯在竞选后才公布，所以第一晚的死者也参加）。所有人同时决定是否上警 → 警上依次发言 → 警下投票，平票 PK 一次，再平票则警徽流失。警长 1.5 票，决定发言方向并最后发言；死亡时可以移交或撕毁警徽。
2. 公布昨晚死亡的座位（不公布死因和身份）。第一晚的死者有遗言，之后夜里的死者没有；白天被放逐或被猎人带走的都有遗言。
3. 猎人出局时可以开枪带走一人（被毒死不能开枪）。
4. 存活玩家依次发言，然后放逐投票（可以弃票）；平票 PK 一次，再平票当天无人出局。
5. 白痴第一次被放逐时翻牌免死，之后不能投票；白痴是警长的话警徽流失。

**胜负（屠边）**：狼人全部出局好人胜；神职全部出局或平民全部出局狼人胜；同时达成时狼人胜。胜负一旦达成立即结束。

人类玩家可以选择身份：随机（默认）、好人随机、狼人，或者某个具体身份。选择只有本人知道。

**出局后和对局结束后**：玩家出局后，等遗言、猎人开枪、移交警徽都处理完，页面就切换成和观众一样，能看到所有身份、夜里的行动和 AI 的思考摘要（打开上帝视角）；对局正常结束后所有玩家都是这样。结束后可以开启赛后交流（可以开多轮）。

## 设计要点

**信息隔离**
- 服务端是唯一知道全部信息的地方。每条事件都标注了可见范围：公开、仅某些座位（例如狼人夜聊只给狼人，查验结果只给预言家），或仅观众。
- 每个 AI 收到的内容，是它能看到的事件渲染成的文本，以新的 user 消息追加到它自己的会话里。
- 人类玩家的推送同样在服务端过滤：夜里谁在行动、狼人夜聊的流式文字都只推给有权看的人。玩家能不能看到全部信息也由服务端决定，切换时重推一遍。

**防止从时间推断信息**：有人类参与时，夜里每一步（狼人、女巫、预言家）至少等 6 到 9 秒，角色已经出局也照常等，避免从夜晚的快慢推断女巫、预言家是否存活。没有遗言的出局处理（猎人决定是否开枪、警长移交警徽）也不对其他人显示"正在行动"。

**AI 进程的限制**（见 `server/ai/player.ts`）
- 关闭全部内置工具（`tools: []`），不加载 `~/.claude` 和项目里的设置或 CLAUDE.md（`settingSources: []`），也不挂 MCP、插件和 skills。
- 权限模式是 `dontAsk`，并且 `canUseTool` 一律拒绝。
- 工作目录是一个空的临时目录。
- 打开 `verbatimPrompts`；发言里的 `<` `>` `@` 和"【裁判】"会被转义，防止伪造裁判消息或其他玩家的发言。
- 启动 AI 进程前，会去掉宿主环境带进来的会注入额外上下文的环境变量。

**会话与缓存**
- 每个 AI 一个 Agent SDK 会话，每次行动都 resume 同一个 session id，记录在 `data/games/<id>/game.json`。
- 在大厅删除一局时，会同时删除这局的记录和所有 AI 的会话记录。进行中的对局不能删除。
- 系统提示词对所有 AI、所有对局都一样；座位、身份都放在第一条 user 消息里。
- 所有动作共用一个结构化输出 schema，避免缓存失效。
- 页面上的估算费用按每个 AI 会话的增量累加（SDK 返回的是会话累计值）。

**思考过程**：只使用 API 官方提供的思考摘要（`display: "summarized"`），不要求模型在输出里写出推理过程。

## 已知限制

- 只有 12 人预女猎白一种板子；没有守卫、狼王、白狼王等其他身份。
- 不支持狼人白天自爆，也不支持上警后退水。
- Claude Code 会把登录账号的邮箱作为用户上下文注入每个会话。它不影响游戏公平，但 AI 能看到。
- 服务进程重启后，进行中的对局会被标记为中止，不支持续局。
- 同一时间只能进行一局。
